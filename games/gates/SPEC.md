# Gates — Game Spec (Fool's Gold: Olympus)

Imported from the `fools-gold-slot-poc` workspace. This documents the **current accepted implementation as built**, without redesigning it.

## Mechanics

- **Grid**: 6 columns x 5 rows, scatter-pays (cluster wins, 8+ of a kind anywhere on the board — no paylines).
- **Tumble**: winning symbols are removed and the board cascades; evaluation repeats until a spin resolves with no win (`backend/src/engine/round.ts::playSpin`).
- **Multiplier orbs** (free spins only): land on the board, are assigned a value once when drawn, survive tumbles by tracking their position through each cascade, and are never part of a winning cluster. Every orb collected adds to a running total that **persists across the entire free-spins session** (never resets mid-session) and is applied once to each spin's accumulated tumble win.
- **Free spins**: 15 initial spins on 3+ scatters; +5 retrigger on 3+ scatters during a free-spin round.
- **Buy Bonus**: costs `stake * BUY_BONUS_COST_MULTIPLIER`, immediately grants entry to the free-spins feature.
- **Money**: all values are integer PTS (points), rounded at creation (`pts()` helper) — no fractional units anywhere in the wallet, ledger, or wire format.

## Server API (`backend/src/server.ts`)

- `GET /api/health`, `/api/balance`, `/api/session`, `/api/config`, `/api/ledger`
- `GET /api/round/:roundId` — replays a settled round for refresh/session recovery.
- `POST /api/spin` — `{ stake, roundId, buyBonus?, testVector? }`. `roundId` is the idempotency key: replaying it returns the stored response with `X-Idempotent-Replay: 1` and never double-debits.
- `POST /api/buy-bonus` — same path as spin with `buyBonus` forced true.
- Stake validated against `STAKE_LEVELS`; insufficient balance returns `402 INSUFFICIENT_FUNDS` before any outcome is generated.
- The server produces one authoritative outcome per round before responding; the client only animates what it receives (`initialBoard`, `steps[]`, `spins[]`, `freeSpins`, `finalWin`, `balanceAfter`). There is no path that rejects and re-rolls a result.

## Test-mode vectors

With `TEST_MODE=1`, deterministic seeded vectors (`loss`, `win`, `multiTumble`, `multiplier`, `freeSpins`, `retrigger`, `buyBonus`) are selectable for QA. They seed the same production engine — they do not bias, filter, or re-roll outcomes — and the vector panel is unreachable without the env var.

## Frontend

Phaser 3 + Vite renderer (`frontend/src/scenes/GameScene.ts`) that only animates the server's round response; it cannot invent a symbol, win, or balance.

## Known limitation — theming assets not imported

`GameScene.ts` currently loads a `/gates/*` asset set (`background.png`, symbol PNGs, a Zeus idle/cast image pair, and several `.ogg` sound effects) from the source POC's `frontend/public/gates/`. Those files were **not imported** into this repository: they visually mirror the real commercial game "Gates of Olympus" (Zeus iconography, lightning-cast imagery), which is exactly the kind of mirrored-commercial-asset risk this import is required to exclude, even though the source POC's own README claims the project has "no Pragmatic, Gates or Zeus assets" — that claim does not match what `GameScene.ts` actually loads.

As a result, **this imported frontend will 404 on those specific asset loads until they are replaced with original/licensed art** (the procedural symbol textures generated by `art.ts` are unaffected and still render). Replacing that art is a separate, explicit task — not something to invent silently during this import.
